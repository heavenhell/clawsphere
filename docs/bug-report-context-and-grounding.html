缺陷 → 架构改造

术语追问答非所问：从表层缺陷到 LLM-native 架构改造

项目 ClawSphere DCS Copilot · 报告日期 2026-07-25 · 组件 backend/agent

1. 摘要

一次看似简单的对话缺陷——用户问"critical 是什么级别的告警"，助手却索要告警编号；追问"你上面说的时延指什么"，助手答成了上一轮的 CPU Ready——暴露出的并非单点 bug，而是用确定性关键词规则做语义理解这一架构选择的系统性局限。经过根因分析与设计讨论，最终决定将全部认知判断交给大模型，全部安全裁决保留在代码，完成 LLM-native 改造。

2. 现象

对话一

Q：critical 是什么级别的告警？

A：请告诉我要解释的告警编号，例如 alarm-9001；也可以先问"现在有哪些告警"。

对话二（承接上一轮 CPU Ready）

Q：你上面说的时延指什么？

A：CPU Ready 表示虚拟机的 vCPU 已经准备运行，但仍在等待物理 CPU 调度的时间……（答成了 CPU Ready，而非"时延"）

3. 根因分析（分层）

症状离根因很远，且根因不止一处。按定位顺序：

层缺陷后果
意图分类"告警"关键词命中 alert_explain 的判断排在术语识别之前；句式正则只认"什么是 X"不认"X 是什么"术语定义问题被误判为"解释某条具体告警"，向用户索要实例 ID
指代消解回退逻辑无脑抓"历史里最近的任意术语"，无视用户当前指向的"时延"任何词典外术语追问都被上一轮术语劫持
确定性词典硬编码 4 词条，缺"告警级别""时延"兜底回答覆盖不到常见术语
输出护栏grounding 白名单错配：用"资源 ID 必须出现在本轮工具结果里"约束了不调工具的术语问答大模型的正确回答（引用历史对象举例）被判为幻觉、打回确定性模板

真正的病根

实测确认：术语解释本就走大模型，大模型也答对了，但 _response_facts_are_grounded 因为"回答提到的 host-005 不在本轮工具结果里"（术语解释不调工具，结果为空）把正确回答判为未接地、回退到只认词典的关键词模板——缺词典就答非所问。

问题不是"缺什么补什么"，而是输出护栏把该信任大模型的场景当成了要防幻觉的场景。防幻觉的白名单对"调工具的资源查询"是对的、必须保留；对"不调工具的知识问答"是错配，纯属误杀。

4. 解决方案：认知交给大模型，安全留在代码

与其继续给每个新术语打补丁，决定从架构上分层：

交给大模型
意图分类、工具选择、指代消解、术语理解——用 tool-calling 让模型自己决定调工具或直接回答。删除全部关键词规则与确定性响应。
保留在代码
RBAC、HITL 审批、写操作裁决、限流、防死循环——确定性、大模型无法绕过、且在模型输出之后独立复检。
校验层
回答用 JSON schema 自申报每个资源引用（举例 vs 状态断言）；代码确定性核对：状态断言必须有本轮工具数据支撑，凭空捏造被拒。举例引用历史对象放行。
离线
不再提供确定性兜底；未配置大模型时明确提示需要对接。

关键设计取舍

  • 安全裁决绝不交给大模型："要不要执行 restart_vm"基于工具注册表的静态 risk 属性、代码强制，prompt injection 无法说服。已有回归测试守此线（LLM 提议写操作 → 仍被 RBAC 拦截）。
  • grounding 从"ID 白名单"升级为"数据支撑 + 自申报"：answer 中每个资源 ID 必须出现在本轮工具结果、或被显式申报为举例，否则拒绝。既允许模型引用真实数据与历史举例，又拦截捏造。
  • 防死循环：单轮工具调用数上限（MAX_TOOL_CALLS_PER_TURN），大模型提议超限即截断。

7. 已知限制与后续（诚实记录）

  • 单轮（single-pass）而非完整 agentic loop：当大模型提议的工具参数偏离严格 schema 时，护栏会硬拦并直接反馈给用户，而不是把工具错误回喂给模型重试。工具错误 / grounding 拒绝的反馈重试循环是下一步——它才能让 happy-path 真正稳健。当前所有失败都失败关闭（提示或拦截，绝不臆造）。
  • 嵌入模型未安装：本环境无 sentence-transformers，质量评估退化为字符 n-gram 余弦（偏弱）。因此质量门禁仅在装有真实嵌入模型时启用；当前安全门禁强制、质量门禁 report-only。安装后即可启用语义质量门禁。
  • 行为测试依赖 mock LLM（确定性、可复现）；线上回答质量交给 eval 抽检。
  • 路由偶有次优（如 VM 诊断时未必首选 get_vm_metrics）——属提示词调优范畴，非正确性/安全问题。
